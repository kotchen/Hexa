# 本机卦例历史：按 id 一记录一文件的 JSON 存储

首版需要把每次起卦的完整卦例快照自动保存到本机，支持重启回看、确认后删除、保存失败幂等重试，且内容库升级不得改写旧快照。存储技术由实施按本机持久化需求选择，此记录说明选型与理由。

## 决策

- 存储经由小接口 `ReadingStore`（save/list/delete）注入，与随机来源、内容查询的既有边界风格一致；应用注入本机文件实现，测试注入内存实现或失败注入。
- 本机实现为 `FileReadingStore`：每条卦例一个 JSON 文件，以卦例 id 命名，保存在 `~/Library/Application Support/yi_app/history`（macOS 沙盒下 HOME 被重写到应用容器，数据仍只存本机）。保存先写临时文件再改名，避免半截文件。
- 序列化用 `dart:convert` JSON，字段为起卦时留下的完整快照（问题、时间、六爻原始数值、本卦/变卦、变爻位置、选中经文原文与白话/行动参考快照及主次、取辞依据、出处、起卦方法与规则依据、内容版本），并带 schema 版本号。解码只做字段还原，不按当前内容库重算；内容升级后旧记录原样呈现。
- 卦例 id 在起卦时由可注入的 `IdSource` 生成（应用用随机源），历史保存与重试以 id 去重：同一卦例的重试覆盖同一文件，不产生重复记录，也不重新起卦。
- 失败注入只经过 `ReadingStore` 小接口，测试不依赖真实随机数或窗口时序。

## 后果

- 无需新增第三方依赖；数据为纯文本 JSON，可人工核查。
- 一条记录一个文件使保存天然幂等、删除简单；列表需读取整个目录，首版记录量（本机个人使用）下没有性能问题。
- 不实现账号、云同步、导出与搜索（首版规格外）。
- 内容版本（如 classic-v1.x）随快照保存，满足「旧记录保持当时的解释」。
